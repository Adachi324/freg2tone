# MVP 方案比较与待定事项

## 画面、素材与渲染方式（2026-09-20）

当前结论：用户在最初选择真实 3D 固定镜头后，进一步选择平面与 3D 混合的体验方向。平面承载知识介绍及简单玩法，较复杂关卡可使用 3D；3D 部分沿用固定镜头。用户偏好绘本氛围、翻页感及从 2D 进入 3D，但弱化实体书概念，游戏感优先。以下保留决策时的候选和成本分析，具体素材制作方式、框架及引擎尚未选定。

用户询问固定斜俯视与可转动镜头的 3D 是否都需要 3D 素材，因此开发成本相同；同时指出平面 2D 可采用贴图与骨骼动画。

需要区分画面视角与实现路线：

| 路线 | 素材与实现 | 成本判断 |
| --- | --- | --- |
| 平面 2D | 2D 场景和角色，可用骨骼或逐帧动画 | 取决于美术风格、动作量、场景数量和复用方式 |
| 2D 素材的斜俯视 | 以固定角度绘制的精灵、图块或背景，通过摆放与前后遮挡表现纵深 | 不强制要求 3D 模型；需处理角度一致、遮挡顺序和所需角色朝向 |
| 固定镜头的真实 3D | 模型、材质、绑定动画和真实 3D 场景 | 与自由镜头 3D 共享大量资产工作，固定镜头主要缩小镜头、可见角度和交互验证范围 |
| 可转动镜头的真实 3D | 在 3D 场景上提供镜头控制与多角度观察 | 除资产外，还需根据实际设计处理镜头操作、遮挡、多角度可读性及触控输入 |

助手评估：固定镜头不能自动消除建模成本，也不能仅凭“2.5D”推断成本低。2D 与 3D 的总成本仍取决于素材来源、质量要求、动画方向和动作数量、场景复用及修改方式。现阶段没有定量工期估计。

官方能力依据：[Unity 等距 Tilemap 文档](https://docs.unity.com/en-us/engine/6000.6/manual/unity2d/tilemaps/isometric-tilemap)说明可用 2D 网格模拟具有高度和纵深的环境。这只用于核对“斜俯视不必使用 3D 模型”的事实，不代表选定 Unity。
