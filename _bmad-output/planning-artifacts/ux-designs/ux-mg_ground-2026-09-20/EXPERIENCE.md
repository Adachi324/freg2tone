## Foundation

手机横屏触控优先，兼容 PC；浏览器为首轮试用载体。用户已认可进入 → 知识介绍 → 对照示范 → 引导练习 → 独立挑战 → 场景结果的流程方向。视觉参考见 DESIGN.md。本文件为草稿；表中标记“提案”的行为尚待确认。

平面承载知识介绍和简单玩法；较复杂关卡可用固定镜头 3D。助手建议按交互对空间的需求选择表现，不机械绑定“学习是 2D、考试是 3D”。教学复杂度与空间复杂度需分别判断。未要求每一关都切换维度。

## Information Architecture

| 表面 | 用途 | 进入与离开（提案） |
| --- | --- | --- |
| 平面游戏场景 | 目标、角色、可操作音乐对象；支持简单关卡 | 打开 Demo 后进入，点选相关对象触发本节教学 |
| 知识介绍区域 | 解释概念、用途及适用条件，随后对照示范 | 在场景内展开；解释完成后进入引导练习，可主动回看 |
| 立体游戏场景 | 承载确实需要空间关系的机关与挑战 | 当前任务需要时由平面展开，保留对象身份联系 |
| 场景结果 | 展示音乐操作带来的实际变化与角色行动 | 原位反馈后完成本单元，可重玩；不另设大型结算大厅 |

早期灰度线框用于讨论六阶段流程，尚未适配混合视觉。当前概念图只用于讨论气质及平面/立体连续性。知识介绍布局正在通过[教学关键画面提案](.working/key-learning-notes-2026-09-24.md)具体化，三个状态不代表完整教案，也不构成学习或可用性验证。

## Voice and Tone

提案：短句说明当前目标和知识关系，解释操作为什么产生结果。游戏感不能成为隐藏知识介绍的理由。具体课程文案在内容制作时确定，不提前固定唱名体系。

## Component Patterns

| 对象 | 行为 |
| --- | --- |
| 场景目标 | 已确认点选后角色自动靠近，再直接操作机关；平面机关是否始终需要角色靠近待具体布局确定 |
| 知识介绍 | 明确介绍概念后才要求练习；可分段，不能以“点击这里”代替教学 |
| 对照示范 | 解释文字、声音、标记和对象之间的关系；提案提供重看入口 |
| 引导练习 | 玩家亲自应用，帮助需关联知识；不能仅播放自动通关演示 |
| 独立挑战 | 撤去逐步答案提示，应用刚学的关系；主动求助后区分辅助完成与独立完成 |
| 场景过渡 | 2026-10-16已确认：当前花园镜头始终固定，教学面板展开/收起带来纸面感；收起即进入挑战，不等待整场翻转 |

## State Patterns

| 状态 | 行为提案 |
| --- | --- |
| 介绍/示范 | 当前教学目标清晰，说明与示例并排；随时重看当前示范 |
| 选择/尝试 | 显示选中对象与可操作目标；手势待布局确定 |
| 未成功 | 机关局部反馈与说明，保留上下文，允许就地替换重试 |
| 使用提示 | 返回相关解释或示范，再回到当前尝试；具体状态恢复规则待实现规格 |
| 达成目标 | 声音、机关变化与角色行动形成可识别的因果反馈 |
| 暂停/离开 | 提案暂停声音与当前动作，回来可继续本次体验；不因此承诺跨刷新或跨设备存档 |

## Interaction Primitives

以点击/轻触为共同基础。选择后放置是当前候选，不把精确拖拽或自由旋转镜头作为前提。教学与挑战中的材料保持身份一致，在同一立体场景中操作。

## Accessibility Floor

已确认音视同步；无声时以文案和状态变化承载适合视觉表达的内容，不将视觉任务作为听觉学习的验证。提案用形状、文字或轮廓同时表达状态，避免只靠颜色。减少动效时仍需理解过渡前后的关系；具体实现与触控尺寸在后续规格中验证。

## Responsive & Platform

横屏手机为主要布局检查对象。兼容平板与 PC 时保持相同操作逻辑，不依赖悬停才能发现重要操作。竖屏提示、窄屏教学布局与镜头具体构图待关键画面收敛。

## Key Flows

### 用户本人：空闲时体验一个学习单元

1. 进入一个可识别目标与音乐对象的平面游戏场景。
2. 触达当前对象后展开知识介绍，先知道概念是什么、用来做什么。
3. 观看带解释的对照示范，可重复观看。
4. 亲自做一次引导练习，观察知识怎样作用于音乐对象。
5. 首个 Demo 在教学和引导练习后，将同一组音乐对象展开为固定镜头 3D 场景，接受一次独立挑战。该安排用于验证一次维度过渡，不规定后续每节课都需切换维度。
6. **关键反馈：** 音乐操作驱动机关变化，角色完成动作，玩家看懂自己刚学的内容发挥了什么作用。

六阶段结构已获认可，步骤中的具体触发和维度安排为提案。失败则在当前尝试中获得解释与重试机会。

2026-10-13 用户进一步确认首个 Demo 小范围包含一次 2D → 3D 过渡，以上第 5 步的范围据此收敛；具体动效仍为提案。

## 声音与过渡

已确认用户被翻页声和纸张质感的交互吸引。提案：说明展开/收起与场景切换使用轻量纸张拟音；材料操作使用对应音乐声音。翻页声在教学示范开始前结束，避免遮住需要辨认的音。静态画稿不能验证该时间关系，需在后续动效和音频样例中检查。

### 首个 Demo 的单次维度过渡

**已确认范围：** 同一小场景、同一组音乐材料与机关；完成平面教学与引导练习后进入立体挑战，过渡后镜头固定。只新增一次过渡，不新增第二套关卡、自由镜头或额外音乐知识。

以下是用于技术预研的具体行为提案，尚未验证动态效果：

| 状态 | 画面与行为 |
| --- | --- |
| 展开前 | 引导练习完成，保留角色、材料和目标；玩家主动进入挑战后收起教学区域 |
| 展开中 | 地面和机关逐步呈现厚度与空间关系，角色及音乐标记保持可识别；镜头只作预设过渡，期间不接收材料操作 |
| 展开后 | 镜头固定，关键对象仍可见，触控/鼠标点选方式延续，开始独立挑战 |

回看教学建议使用当前立体场景上的平面说明，关闭后保留当前尝试，不再往返切换整个世界；失败在原场景重试，不重复过渡。减少动效时建议直接切换到最终固定镜头并保留简短状态提示。按住拖拽不作首轮必需操作，建议先用“点选材料 → 点选槽位”；这些细节由后续交互验证收敛。

**预研需回答：** 同一对象是否能在两种呈现中持续辨认；转换后是否需要重新寻找目标；手机横屏能否清楚点选；翻页拟音与教学声音是否互相遮盖；三维部分是否呈现实际几何、遮挡与机关运动。不能只用两张插画淡入淡出就宣称已验证真实 3D。具体动效时长和性能阈值在选定验证设备后定义，不先编造数值。
