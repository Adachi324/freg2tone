# Demo 体验提案 · 待讨论

这是基于已确认方向的首份流程与布局提案，不是最终 UX 契约，也不是可运行游戏。DESIGN.md 与 EXPERIENCE.md 已整理为包含已确认方向和明确标记提案的草稿，尚未定稿。当前参考：[范围草案](../../../prds/prd-mg_ground-2026-09-18/prd.md)、[流程线框](demo-flow.html)、[视觉概念候选 v2](hybrid-world-v2.png)。

用户已认可补齐后的流程方向：进入 → 知识介绍 → 对照示范 → 引导练习 → 独立挑战 → 场景结果。此认可仅针对流程合理性，不扩展为具体机关、材料安装手势、线框布局或美术风格的定稿，也不代表学习效果已验证。下一步讨论视觉气质与参考，再以画稿收敛表现。

## 已确认与本次提案

已确认：通用乐理；Learn → Test 主线；音名与唱名作为首个载体；移动端优先兼容 PC；横屏、平面与固定镜头 3D 混合、独立小场景；点击目标后角色自动靠近，再直接操作音乐机关；音乐操作需产生可听、可见的场景结果。

本次提案：用可安装音乐材料的机关表达知识应用。点选材料再点选机关中的位置完成安装或替换；拖拽不是当前前提。名称标记与发声部件属于同一个机关，关系正确时部件产生声音并驱动场景变化。此处的“正确”依赖后续教案，不先规定唱名体系，也不把机关外观、名称或候选映射解释为已经确认的玩法。

## 一次体验

以用户本人为首轮试用者：空闲时用手机横屏打开体验，先接触熟悉的基础内容，检查玩法是否能承载学习。流程如下。

| 时刻 | 玩家做什么 | 场景怎样回应 | 需要检查什么 |
| --- | --- | --- | --- |
| 进入 | 看见角色、目标机关与当前小任务；点选机关 | 角色自动走到交互位置，机关成为视觉焦点 | 不经长说明能否找到操作对象 |
| 知识介绍 | 先了解本节概念是什么、用来做什么 | 教学区显示可读的解释，场景保留但暂不要求解题 | 玩家是否真的接触到了新知识，而不只是知道点哪里 |
| 对照示范 | 观察系统演示一个例子，可重复观看 | 声音、名称和部件同步呈现，并解释其中的关系与适用条件 | 能否将抽象概念与眼前实例联系起来 |
| 引导练习 | 亲自应用刚介绍的知识，需要时回看讲解 | 部件响应并解释操作结果，提供知识关系上的帮助 | 玩家能否理解原因，而非只跟着亮光点 |
| 独立挑战 | 在同类机关的新实例中运用刚学的关系 | 不再显示答案引导，仍显示任务和可操作部件 | 能否依靠知识完成，而非记住按钮位置 |
| 尝试未成功 | 更换自己放入的材料，必要时请求提示 | 显示尚未生效的部件和对应说明，允许就地再试 | 能否理解还需调整什么；是否必须盲猜 |
| 达成结果 | 观察结果，可重玩 | 部件声音与机关变化对应，角色自动通行或完成当前动作 | 玩家是否感到自己通过音乐知识使场景发生了变化 |

高潮落在机关真实生效与角色行动的时刻。结算文字只补充说明，不能代替场景本身的反馈。

## 画面与行为提案

场景主体保留角色、路径与机关。当前任务短句位于画面边缘。知识介绍使用独立教学区域；对照示范让解释与声音/部件并排出现；引导练习再把提示放回具体操作附近。复杂概念可拆成多个教学片段，不要求在机关旁一个气泡里讲完。材料优先在机关附近呈现；若手机横屏无法清晰点击，再比较局部放大或边缘操作区，不能通过缩小文字硬塞。

进入、讲解、尝试、成功使用相同的空间关系。独立挑战可切到下一个小场景并复用同类机关；本次线框只表达该结构，不要求制作连续世界或课程地图。候选提示包括局部指示、可重复的演示和简短解释，具体内容待教案。

无声情况下用文字和状态变化呈现结构，不将结构操作记作听觉辨认。基础音频交互和音视同步必须在可玩版本中验证，静态线框无法证明。触屏和鼠标均不依赖悬停或精细拖拽；需要可辨认的选中、可放置、已生效与可重试状态。

## 本轮评审焦点

视觉参考进展：用户明确喜欢《勇敢小骑士》的绘本氛围、翻页感觉和由 2D 进入 3D 世界。要求弱化实体书的概念，让人首先感到在玩。平面可呈现知识，也可承载简单玩法；较复杂关卡可由 3D 承接。这更新了先前统一 3D 场景的假设，3D 部分仍沿用固定镜头。六阶段教学流程继续成立，但现有灰度线框尚未体现混合呈现，需要在下一版补上。

当前助手提案：同一组音乐材料与机关在两种空间中保持身份和外形联系，以场景表面卷起、展开或物体立起表达翻页感；教程像场景内可展开的平面区域。具体变换方式、配色和造型待概念图评审，不是用户已定方案。2D 不等同于只阅读，3D 不等同于所有测试；按交互是否需要空间来安排表现，避免为了变成立体而增加无关操作。静态概念图仅检查氛围与连续性，动画、翻页音效、教学和玩法有效性仍待后续验证。

先检查学习链路是否完整：是否先介绍概念、演示并解释例子，再让玩家在帮助下应用，最后撤去帮助进行独立挑战。原四步线框漏画了知识介绍，只呈现操作提示；本次补成六个状态，不能把操作指示称作知识教学。

同时检查音乐材料是否像机关本身的一部分，操作是否使场景发生有意义的变化。若看起来仍像答完选择题再播放开门动画，需要重新设计操作与机关的关系。

布局成立后再讨论视觉气质与角色/机关造型，补充关键状态并转成 UX 契约；随后进行必要技术选型、规格与实现。线框中的灰度、几何块、视角和占位文案仅用于讨论，不是用户已选的美术方向或最终课程。
