## 性能与稳定性起始预算

以下是本轮提出的工程排查线，允许依据实测与体验修改；不是来自机型跑分或用户性能承诺。

- 主测手机前台可见状态下，分别覆盖角色靠近、重试及成功动作；每轮连续采集至少 30 秒，运行三轮，记录动态阶段 rAF 间隔 P50/P95/最大值。暂以 P95 ≤ 33.3 ms、无单次 ≥ 200 ms 停顿为检查线。重复动作可拼接样本，但不能拿大量静止帧稀释动态问题；后台和人工暂停分开记录。
- 连续进行 20 轮错误→正确→复玩、至少 5 次后台恢复，不出现状态串扰、重复角色通行、卡音或无响应。测试次数是小样本回归规模，不代表长期可靠性证明。
- 记录冷缓存首次加载到可操作的时间、网络条件、实际传输资源大小；先建立基线，不在网络条件未知时设固定秒数承诺。开始、重试均须有可见加载/失败状态。
- rAF 间隔只表示浏览器调度表现，不等于 GPU 实测帧率，也不能测量声学延迟。音频先记录扬声器下主观跟手、遗漏/重叠及恢复情况；耳机测试单独列出输出设备。若明显不同步，再做外部录音录像测量，不能以 JS 回调时间宣称实际声音同步。

未达排查线时，定位素材、绘制、状态或音频原因并记录修复；不能通过删除真实 3D 或声音把关键风险隐藏。主观体验通过而性能预算未达时，也须保留差异供路线决策。

## 每次验证的记录字段

记录日期、代码/构建标识、依赖版本、访问地址、设备、iOS/浏览器版本、横屏 viewport、音频输出设备、网络与缓存状态、测试步骤、预期/实际、通过/失败/未测，以及必要截图/录像。未建立 Git 仓库时用构建标识或文件哈希，不伪造 commit。

iPhone 13 Pro Max 为已确认主测设备，Safari 为默认假设。PC 检查同操作逻辑；平板和 Android 未指定、未测试时明确标注，不扩写为兼容结论。实际真机可由用户按步骤操作并回报，助手没有设备控制能力时不能声称已代测。

## 路线结论

仅当规则/集成通过、主测设备检查有证据且用户认可动态效果时，记录“该设备上的候选路线可继续”。代码通过但缺真机或风格评审时记录“技术样本完成，体验待验证”。关键风险失败则带着复现结果调整资产/实现，必要时比较备选引擎；不会自动升级为完整 Demo 开发。
